# Decision 0009: Use replicated hardware feedback for target profiles

- **Status:** accepted for exploratory H1
- **Date:** 2026-08-01
- **Owners:** project owner; implementation delegated to Codex
- **Reviewers:** independent compiler/performance review required before host
  feedback can affect online execution or vocabulary generation
- **Scope:** existing E-H0 vocabulary entries at `(R4, M3, G2, L2, D0; F3)`

## Context

E-H0 learns transparent vocabulary from deterministic execution-weighted
evidence, and B0 shows that learned cycles can reduce runtime on the current
host. B0 also shows substantial session noise, non-monotonic cycle ordering,
and regression when learned phrases are absent. Decision 0008 therefore
forbids selecting or retiring vocabulary from a single noisy benchmark.

The next project step should connect real hardware evidence to language
lifecycle without allowing timing noise to change primitive meaning, generate
opaque instructions, classify live workloads, or deploy code.

## Decision

H1 may use replicated host measurements to freeze an offline, target-specific,
pit-specific vocabulary profile under these rules:

- pin the CPU model, operating system/release, machine architecture, generated-C
  backend, compiler path/version, and flags before measurement;
- run an odd number of complete matched B0 sessions, with five sessions by
  default;
- require exact checksums in every session;
- compare LAIcode cycles within the same session and backend;
- require a deterministic weighted-token reduction before any learned cycle is
  eligible, regardless of measured speed;
- require at least 5% median paired improvement and an 80% paired-session win
  rate by default;
- choose the eligible cycle with the lowest median of session medians, falling
  back to cycle 0 when no learned cycle qualifies;
- freeze active and retired entry identities independently for every registered
  pit; and
- interpret retirement as exclusion from that target profile, never deletion
  of the entry, lowering, lineage, or negative evidence.

The target profile is executable only when an external caller supplies a known
registered pit. H1 does not infer the current workload from timing and does not
route or deploy traffic.

## Authority boundary

H1 may activate or retire existing transparent entries in a D0 offline profile.
It may not:

- change primitive semantics or exact lowering;
- generate a new entry from host nanoseconds;
- modify correctness tests, evidence partitions, gates, or target identity;
- delete failed evidence;
- classify an unknown workload automatically;
- alter the deterministic E-H0 selection record; or
- perform D1/D2 execution, canarying, or autonomous deployment.

## Replay and provenance

Raw host timing cannot be regenerated byte for byte. H1 instead archives every
session report, raw protocol output, and runnable artifact; verifies their
identities and checksums; and deterministically rederives the aggregate,
target profile, lifecycle decision, and run report from that archived evidence.
A current CPU/OS/compiler mismatch blocks decision replay.

## Consequences

- Hardware now influences an explicit language lifecycle artifact rather than
  an informal benchmark interpretation.
- Different workload pits may legitimately select different vocabulary depths.
- A fast measurement without representational reuse cannot promote a learned
  vocabulary.
- Sequential sessions on one WSL host are stronger than one run but are not
  independent-machine or confirmatory evidence.
- External workload classification becomes a required integration boundary.

## Validation evidence

Required evidence includes successful multi-session selection, primitive
fallback on no-reuse shift, exact lifecycle-decision replay without rerunning
timings, raw-evidence tamper detection, target mismatch rejection, invalid
session-count rejection, executable target-profile resolution, and synthetic
gate meta-tests that distinguish speed from genuine vocabulary reuse.

## Revisit criteria

Start a new decision before using hardware results to generate vocabulary,
calibrate the learner's cost model automatically, aggregate different CPU
targets, infer workload class, deploy a profile, or retire entries globally.
Require independent machines, randomized session order, calibrated uncertainty,
energy/counter evidence, and an external reviewer before any confirmatory H2
claim.
